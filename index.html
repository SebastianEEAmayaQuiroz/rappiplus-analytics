01
💰
Rentabilidad del negocio
Python · Pandas · KPIs
S — Situación

RappiPlus generó $51.9M en revenue con 24,916 pedidos distribuidos equitativamente entre México, Colombia y Argentina. Hogar, Moda y Electrónica tienen volúmenes muy similares.

C — Complicación

El gasto en marketing alcanzó $2.87M. Sin cruzar revenue con el costo real del catálogo, no es posible confirmar si el negocio opera con profit positivo o en pérdida.

P — Pregunta

¿El negocio genera profit positivo después de descontar costos de producto y gasto en marketing?

R — Respuesta

El análisis confirma que el negocio es rentable. El canal Organic es el más eficiente al no generar costo de adquisición directo. El merge con el catálogo revela el profit real por línea de pedido.

02
🛒
Funnel de conversión
SQL · PostgreSQL · Window Functions
S — Situación

El flujo tiene 5 etapas: first_visit → product_view → add_to_cart → begin_checkout → purchase. Se mide cuántos usuarios únicos llegan a cada paso.

C — Complicación

El mayor drop-off ocurre entre add_to_cart y begin_checkout. El usuario ya mostró intención al agregar al carrito, pero abandona antes de iniciar el pago — la mayor fricción está ahí.

P — Pregunta

¿En qué etapa exacta se pierde la mayor cantidad de usuarios y cuál es la tasa de conversión final?

R — Respuesta

Las funciones FIRST_VALUE y LAG cuantifican cada drop-off. El punto add_to_cart → begin_checkout es la prioridad máxima de intervención de UX para mejorar la conversión global.

03
🔁
Retención por cohortes
SQL · CTEs · Análisis temporal
S — Situación

Usuarios agrupados por mes de registro. Se mide cuántos permanecen activos en las semanas 1, 2 y 3 posteriores a su alta en la plataforma.

C — Complicación

La retención cae semana a semana en toda plataforma de e-commerce. Sin medición por cohorte, es imposible saber si el negocio mejora o empeora su capacidad de retener usuarios con el tiempo.

P — Pregunta

¿Qué cohortes tienen mayor retención y en qué semana se produce el mayor abandono post-registro?

R — Respuesta

La consulta con CTEs calcula semana_1, semana_2 y semana_3 como % del total de la cohorte. Identifica qué mes de adquisición generó los usuarios más fieles y cuándo ocurre el abandono crítico.

04
🧪
Test A/B checkout
Python · SciPy · T-test · α=0.05
S — Situación

Experimento con nueva UI en el checkout. H₀: la tasa de conversión del grupo tratamiento es igual al control. H₁: la nueva UI genera una diferencia significativa.

C — Complicación

El grupo de tratamiento mostró una diferencia vs. el control. Sin un test formal es imposible saber si esa diferencia es real o producto del azar — no se puede tomar una decisión sin evidencia estadística.

P — Pregunta

¿El cambio en la UI del checkout tiene un impacto estadísticamente significativo en la tasa de conversión de compra?

R — Respuesta

p-valor > 0.05 → No se rechaza H₀. La diferencia no es estadísticamente significativa. Se recomienda continuar el experimento con mayor volumen de datos o explorar otros cambios en el flujo de compra.

-- FUNNEL: conversión paso a paso con funciones de ventana
WITH funnel AS (
    SELECT nombre_evento,
           COUNT(DISTINCT id_usuario) AS usuarios_unicos
    FROM   events  GROUP BY nombre_evento
),
ordered_funnel AS (
    SELECT nombre_evento, usuarios_unicos,
           CASE nombre_evento
               WHEN 'first_visit'    THEN 1
               WHEN 'product_view'   THEN 2
               WHEN 'add_to_cart'    THEN 3
               WHEN 'begin_checkout' THEN 4
               WHEN 'purchase'       THEN 5
           END AS orden_funnel
    FROM funnel
)
SELECT nombre_evento, usuarios_unicos,
    ROUND(100.0 * usuarios_unicos / FIRST_VALUE(usuarios_unicos)
        OVER (ORDER BY orden_funnel), 2) AS conversion_vs_inicio_pct,
    ROUND(100.0 * usuarios_unicos / LAG(usuarios_unicos)
        OVER (ORDER BY orden_funnel), 2) AS conversion_paso_anterior_pct
FROM ordered_funnel WHERE orden_funnel < 99 ORDER BY orden_funnel;

-- COHORTES: retención semanal W1 / W2 / W3 con CTEs
WITH cohortes AS (
    SELECT u.id_usuario,
           TO_CHAR(CAST(u.fecha_registro AS DATE), 'YYYY-MM') AS cohorte,
           ua.dias_despues_registro, ua.activo
    FROM users u LEFT JOIN user_activity ua
        ON u.id_usuario = ua.id_usuario
)
SELECT cohorte, total_usuarios,
    ROUND(100.0*retenido_w1/NULLIF(total_usuarios,0),1) AS semana_1,
    ROUND(100.0*retenido_w2/NULLIF(total_usuarios,0),1) AS semana_2,
    ROUND(100.0*retenido_w3/NULLIF(total_usuarios,0),1) AS semana_3
FROM resumen ORDER BY cohorte;
